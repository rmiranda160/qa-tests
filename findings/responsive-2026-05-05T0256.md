## 🔴 Finding 1: Cookie Policy Link Missing Locale Prefix (Broken on ES)

**Severity:** Medium
**Location:** All pages (cookie consent dialog)
**URL in dialog:** `/content/9-cookies` (missing `/es/`)
**Expected:** `/es/content/9-cookies` or locale-aware redirect
**Actual:** Link points to `/content/9-cookies` which 404s on the Spanish version

The cookie dialog's "Política de cookies" link uses a hardcoded path without the locale prefix. On `/es/` pages, this breaks the navigation.

**Recommendation:** Make the cookie policy link locale-aware (e.g., `{$urls.base_url}{$language.iso_code}/content/9-cookies`).

## 🟡 Finding 2: Language Selector Not Accessible on Mobile

**Severity:** Medium
**Location:** Mobile header (≤767px)
**Description:** The language selector (`<select>`) is rendered in the DOM but positioned off-screen (`box=0,0,0,0`). Mobile users cannot change the site language — there is no visible language toggle in the mobile header.

**Desktop/Tablet:** Language combobox visible in the top bar.
**Mobile:** Top bar is hidden; only logo, search icon, login icon, and publish button remain. No language selector alternative is provided.

**Recommendation:** Add a language toggle (icon or dropdown) to the mobile header, or include it in a hamburger menu if one is planned.

## 🟡 Finding 3: Console Errors — GSI/FedCM & Empty Provider List

**Severity:** Low
**Location:** All pages (3 errors/page)
**Errors:**
1. `Provider's accounts list is empty.` — Google Sign-In provider list not initialized
2. `FedCM get() rejects with NetworkError: Error retrieving a token.` — from `accounts.google.com/gsi/client`
3. `Unexpected token '&'` — likely a `JSON.parse()` receiving malformed URL-encoded string

**Impact:** These may cause social login (Google) to fail for real users. The `Unexpected token '&'` suggests a JS bug with query string parsing.

**Recommendation:** Fix the Google Sign-In initialization to handle empty state gracefully. Investigate the `JSON.parse()` call that receives URL query strings.
